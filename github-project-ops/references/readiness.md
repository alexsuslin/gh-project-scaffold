# Inspect and adopt existing projects

Use `scripts/scaffold.py doctor PATH` for a read-only inventory. Use `adopt PATH
--preview` when the task includes adding agent guidance to an existing repository.
Run with Python 3.11+ and Git. Neither command imports Copier or requires a network
connection; invoking through `uv run` can still install the script's Copier dependency.
Prefer direct Python for offline diagnosis.

## Doctor contract

`doctor PATH --json` returns `schema_version: 1`, `requested_path`, effective `root`,
`git`, `stacks`, `commands`, `instructions`, `handoff`, `adoption`, `copier`,
`findings` and `checks_executed: false`.

- `git`: root, HEAD (null before the first commit), branch (null when detached),
  dirty state when available, and registered worktree paths. If Git discovery fails,
  immediate child repositories are listed as `nested_roots`. Missing Git and failed
  Git inspection are findings, not assertions that a directory is safe to initialize.
- `commands`: candidate name, command, source and `verified: false`. The CLI never
  executes these commands or prints raw package scripts, environment files or remote URLs.
- `findings`: stable code, severity (`info`, `warning`, `error`), and explanation.
- `adoption`: validated local provenance manifest, or null. Hashes describe original
  generated bytes; subsequent handoff/instruction edits are expected and preserved.

Exit 0 means no warning/error findings, **not** passing tests or production readiness.
Exit 1 means findings need review. Exit 2 means invalid input/operational failure;
JSON mode returns `schema_version` and `error` for invalid destinations.

Discovery is deliberately bounded. Python and Node metadata are inspected at the
root; .NET project markers are inspected at the root and one level below it. Godot,
Terraform and Ansible have simple marker detection. This does not fully analyze
monorepos, nested infrastructure layouts, workflow YAML, shell scripts or dependency
graphs. Missing detection is unknown, not an instruction to replace the existing stack.
Files inspected as text are limited to 1 MiB and must be regular UTF-8 files.

Python check candidates come from pytest, Ruff, Mypy and Pyright configuration in
`pyproject.toml`. A root `uv.lock` selects `uv run --locked`; otherwise candidates use
`python -m`. Mypy uses configured `files`, `modules` or `packages` when present and
suggests `mypy .` when no targets are configured. Pyright uses its configured scope.
Node candidates require exactly one recognized npm/pnpm/Yarn lockfile and known
script names.
For .NET, doctor suggests `pwsh -File ./build-web.ps1` when that script is a
regular file at the root. It suggests `dotnet run --project` for `*.Tests.csproj`
files in the bounded scan with one explicit, unconditional `OutputType=Exe`.
Discovery reads XML metadata without evaluating MSBuild imports or properties.
Paths with shell metacharacters and linked files are skipped.
These are hints: confirm environment prerequisites and side effects before execution.
No test/build/deploy command is inferred for infrastructure or unknown stacks.

Git calls disable optional locks and filesystem-monitor hooks. No fetch, index write,
package installation or project command is performed. The tool does not inspect the
contents or cleanliness of other registered worktrees; it only lists their paths.

## Additive adoption

```sh
python scripts/scaffold.py adopt /path/to/repo --preview
python scripts/scaffold.py adopt /path/to/repo
# Select an existing continuation document instead of creating another one:
python scripts/scaffold.py adopt /path/to/repo --handoff docs/CONTEXT.md --preview
```

Target the Git root, not its parent or a subdirectory. Dirty worktrees and repositories
without a first commit are supported: existing files and the index are preserved.
Copier-generated repositories are rejected; use their normal `update` flow instead.

The operation creates only missing `AGENTS.md`, the default `docs/HANDOFF.md`, and
`.scaffold.json`. Existing AGENTS.md or AGENTS.override.md suppress new agent guidance.
Other instruction files are preserved. The CLI prints a reminder to link existing
instructions to the handoff instead of rewriting them. An explicit `--handoff` must
point to an existing, nonempty, project-relative Markdown file.

The manifest records schema version, scaffold version, handoff path and SHA-256 hashes
of files created during adoption. It contains no absolute paths, timestamps, private
configuration or fabricated Copier history. It is provenance, not an auto-update policy.
Keep it in Git. Adopted projects do not support Copier updates in this release.

Repeated adoption does not rewrite anything, including modified or deleted generated
files. Use doctor to find missing files; repair deliberately after inspecting the diff.
Changing the selected handoff requires a manual manifest/instruction review.

All proposed paths are checked before writing, including during preview. Symlinks,
Windows reparse points, traversal paths, malformed manifests and file/directory
collisions are rejected. Writes use exclusive creation and the manifest is written
last. On an ordinary write failure, the CLI attempts to remove only its own complete,
unchanged files and empty created directories. A process crash, partial write or a
concurrent filesystem change can still leave additions: inspect the diff before retrying.
Preview and apply are separate inspections; rerun preview if the repository changes.

Exit codes for adopt: 0 applied/previewed/already adopted; 2 invalid or unsafe request.

## Handoff and completion

Use one continuation document. The default distinguishes the goal and acceptance
criteria, revision/working state, implementation, verification, integration, deployment,
evidence, blockers and next action/owner. Scaffold leaves those facts unknown.

Update this document when meaningful state changes, not on every tool call. Reference
existing issue/PR/report evidence; do not paste transcripts or create another backlog.
No field grants deployment permission or proves a successful test. The first release
checks the presence/readability of the handoff, not the truth or freshness of its prose.
